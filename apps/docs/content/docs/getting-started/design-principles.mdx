JDS v3는 Laravel 애플리케이션의 화면을 일관되게 구성하기 위한 Blade 디자인 시스템입니다. 동작의 의미가 분명하고, 기본 사용법이 간단하며, 필요한 부분을 조합하거나 바꿀 수 있는 컴포넌트를 설계합니다.

## 핵심 원칙

### 1. 시각적 형태보다 동작의 의미

JDS의 변형 이름은 화면에서 동작이 맡는 역할을 나타냅니다. 같은 편집 화면에서도 저장, 미리보기, 닫기는 우선순위가 다릅니다.

| 변형 | 역할 | 사용 예 |
| --- | --- | --- |
| `primary` | 화면에서 가장 중요한 동작 | 편집 폼에서 저장 |
| `secondary` | 주 동작 외에 가능한 작업 | 미리보기 또는 수정 |
| `tertiary` | 현재 흐름을 벗어나거나 건너뛰는 동작 | 닫기 또는 건너뛰기 |
| `danger` | 데이터를 잃거나 상태를 되돌리기 어려운 동작 | 계정 삭제 |

하나의 작업 영역에서 주 동작은 하나로 정합니다. 보조 동작은 필요에 따라 여러 개 둘 수 있고, `tertiary`는 닫기나 건너뛰기 같은 경우에 제한적으로 사용합니다.

### 2. 접근성을 기본으로

Blade에서 렌더링되는 HTML에 동작에 맞는 요소와 접근 가능한 이름을 제공합니다. 예를 들어 설정 화면의 탭은 각 탭과 패널이 연결되어야 하고, 키보드로 이동했을 때 포커스가 보여야 합니다. 대화상자를 닫으면 포커스를 열었던 요소로 돌려보냅니다. 렌더링 결과와 브라우저 조작을 함께 확인합니다.

아래 Blade 예시는 설정 폼에서 입력의 이름과 안내 문구를 각각 연결합니다.

```blade
<label for="notification-email">알림 이메일</label>
<input
    id="notification-email"
    name="notification_email"
    type="email"
    value="{{ old('notification_email', $email) }}"
    aria-describedby="notification-email-help"
>
<p id="notification-email-help">주문 상태 변경 알림을 받을 주소입니다.</p>
```

### 3. 설정보다 조합을 우선하기

복합 컴포넌트는 루트와 하위 요소를 Blade에서 조합하도록 설계합니다. 예를 들어 카드는 헤더, 본문, 푸터를 배치하고, 주문 상태나 상세 링크는 필요한 슬롯에 전달합니다. 보조 동작이 없는 카드에서는 푸터를 생략할 수 있어야 합니다.

다음은 카드 템플릿에서 기본 슬롯과 선택 슬롯을 나누는 예입니다.

```blade
<article class="jds-card">
    @isset($header)
        <header class="jds-card__header">{{ $header }}</header>
    @endisset

    <div class="jds-card__content">{{ $slot }}</div>

    @isset($footer)
        <footer class="jds-card__footer">{{ $footer }}</footer>
    @endisset
</article>
```

### 4. 필요한 만큼 점진적으로 설정하기

기본 버튼은 표시할 텍스트만으로 사용할 수 있게 설계합니다. 저장처럼 강조가 필요한 화면에서는 변형을 지정하고, 도구 모음에서는 크기나 아이콘을 더합니다. 폼을 제출하는 동안에는 화면의 상태에 따라 버튼을 비활성화하고 진행 중임을 표시할 수 있어야 합니다.

### 5. 같은 API에서 같은 동작 기대하기

버튼, 칩, 아바타처럼 역할이 다른 컴포넌트에도 `sm`, `md`, `lg` 같은 공통 크기 이름을 사용합니다. 변형, 사용자 CSS 클래스, `data-pressed` 같은 상태 속성도 같은 규칙으로 다뤄, 속성만 보고 동작을 예상할 수 있게 합니다.

### 6. 타입 안전성을 우선하기

Blade 속성마다 허용 값과 생략 시의 기본값을 문서화합니다. 예를 들어 `size`를 지원하는 컴포넌트는 허용하는 크기와 기본 크기를 레퍼런스에 표시합니다. 클래스 기반 컴포넌트에서는 PHP 타입을 활용하고, 입력값을 검증할 때는 어떤 속성에 어떤 값을 전달해야 하는지 알려 줍니다.

### 7. 스타일과 동작을 분리하기

Blade는 의미 있는 HTML과 슬롯을 렌더링합니다. CSS는 테마, 변형, 상태를 표현하고, 브라우저의 상호작용 코드는 키보드 이벤트나 열기·닫기 같은 실제 상태를 관리합니다. 아래 Blade 예시는 네이티브 제출 동작과 CSS 변형, 서버에서 전달한 비활성 상태를 함께 표현하는 방식입니다.

```blade
<button type="submit" class="jds-button jds-button--primary" @disabled($isLocked)>
    변경사항 저장
</button>
```

### 8. 개발 경험을 설계에 포함하기

JDS 레퍼런스에서 기본 사용법, 허용 속성, 슬롯, 접근성 동작을 찾을 수 있게 구성합니다. 예제를 제공할 때는 미리보기와 복사 코드에 같은 Blade 파일을 사용합니다. 에이전트도 [전체 문서](/llms-full.txt)에서 같은 기준을 확인할 수 있습니다.

### 9. 테마부터 슬롯까지 커스터마이징하기

제품 전체의 강조색 같은 값은 테마 토큰에서 조정합니다. 특정 컴포넌트의 표현은 공개 BEM 클래스를 사용해 조정하고, 제목이나 보조 동작 같은 콘텐츠는 슬롯으로 전달합니다. 다크 모드에서도 같은 토큰 이름을 사용합니다. [디자인 시스템](/docs/design)에서 관련 항목을 볼 수 있습니다.

### 10. 조합과 확장을 열어두기

반복되는 화면 구성을 애플리케이션의 Blade 컴포넌트로 묶을 수 있게 설계합니다. 예를 들어 주문 관리 화면의 작업 영역은 공통 저장·취소 배치를 제공하고, 화면마다 필요한 보조 동작을 슬롯으로 받을 수 있습니다. 래퍼는 호출자가 지정한 `id`, 접근성 속성, CSS 클래스를 알맞은 내부 요소에 전달합니다.

## 구현·검수 기준

컴포넌트를 설계하거나 변경할 때는 해당하는 행의 규칙을 적용하고, 마지막 열에 있는 결과를 확인합니다. 기존 컴포넌트는 실제 Blade 태그, 속성, 슬롯, 출력 HTML을 기준으로 검수합니다. 이 페이지의 예제는 설계 원칙을 보여주기 위한 Blade 조각입니다.

| 변경 대상 | 구현 규칙 | 확인할 결과 |
| --- | --- | --- |
| 동작의 우선순위 | 먼저 화면에서 동작이 하는 일을 정합니다. 주 동작은 `primary`, 대안은 `secondary`, 닫기·건너뛰기는 `tertiary`, 파괴적 동작은 `danger`를 사용합니다. | 예를 들어 편집 영역에 `primary` 저장과 `secondary` 미리보기가 있고, 삭제는 `danger`로 표시됩니다. |
| 마크업·접근성 | 동작에는 `button`, 이동에는 링크를 사용합니다. 입력과 컨트롤은 접근 가능한 이름을 가지고, 설명이나 패널은 필요한 경우 대상의 ID로 연결합니다. | 이름과 역할을 접근성 트리에서 확인합니다. 키보드로 활성화할 수 있고, 대화상자를 닫으면 포커스가 트리거로 돌아갑니다. |
| 속성과 슬롯 | 최소 입력에서 기본값을 사용합니다. 선택 영역은 슬롯으로 열고, 속성의 허용 값과 기본값을 명시합니다. | 필수 입력만 전달했을 때 렌더링됩니다. 선택 슬롯을 생략해도 빈 래퍼가 생기지 않고, 슬롯을 전달하면 지정된 위치에 표시됩니다. |
| 테마·스타일 | 공통 색상은 의미 기반 토큰을 사용합니다. 변형과 하위 요소는 공개 BEM 클래스로 표현합니다. | 라이트·다크 모드에서 동일한 토큰이 각 테마의 값으로 적용되고, 추가로 전달한 클래스가 출력 HTML에 남습니다. |
| 브라우저 동작·모션 | 네이티브 동작은 HTML 요소에 맡기고, 브라우저에서 바뀌는 상태는 접근성 속성과 스타일에 반영합니다. 애니메이션은 시스템의 모션 감소 설정을 따릅니다. | 클릭과 키보드 조작 후 화면 상태와 접근성 속성이 함께 바뀝니다. 모션 감소 환경에서도 조작을 마칠 수 있습니다. |
| 문서·확장 | 공개 속성, 기본값, 슬롯, 접근성 동작은 실제 구현과 일치하게 기록합니다. 래퍼를 추가할 때는 호출자가 준 HTML 속성을 의도한 요소에 전달합니다. | 문서의 예제가 등록된 API를 사용하고, 사용자 지정 ID·클래스·접근성 속성이 대상 요소에 렌더링됩니다. |
